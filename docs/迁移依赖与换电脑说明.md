# 迁移依赖与换电脑说明

检查日期：2026-11-20。

本项目的广告规则和生成脚本可以随项目目录搬移。需要在换电脑时调整的部分，主要是局域网订阅地址、后台服务的系统依赖，以及可选的手机测试参数。本文记录检查时的实现状态和迁移步骤；待完善项尚未实现。

## 当前依赖

| 项目 | 当前值或实现 | 换电脑时需要做什么 |
| --- | --- | --- |
| 电脑的局域网地址 | `192.168.2.77` | 使用新电脑的实际局域网 IPv4 地址，并确认手机可以访问 |
| 手机保存的完整配置订阅链接 | `http://192.168.2.77:8765/config.yaml` | 在手机客户端修改链接；仅修改电脑里的配置文件不会改变手机已保存的链接 |
| 两份广告规则的下载地址 | 完整配置中写死 `http://192.168.2.77:8765/ads-merged.mrs` 和 `http://192.168.2.77:8765/ads-merged-extra.yaml` | 一起改为新电脑地址，保留文件名和 `DIRECT` 下载策略 |
| 订阅服务端口 | `subscription_server.py` 中的 `PORT = 8765` | 新电脑需要可用的 TCP 8765 端口；目前没有端口命令行参数 |
| 后台启动、停止 | 使用 macOS 的进程查询、信号和用户目录 | 另一台 Mac 可以沿用；Windows、Linux 目前使用前台运行方式 |
| 三个双击启动脚本 | `.command` 文件使用 zsh 和 `/usr/bin/python3` | Windows 不能直接使用；Mac 上也需要该 Python 路径可用 |
| 局域网地址自动显示 | 只实现 macOS 的 `/usr/sbin/ipconfig` 查询 | 其他系统需要自行查看局域网 IPv4 地址 |
| 手机测试目标 | `phone-tests/test_phone_rules.py` 固定手机 IP、端口、证书指纹和规则集名称 | 换手机、换配置或地址变化时核对；只影响手机调试，不影响提供配置和规则下载 |

服务实际监听的是 `0.0.0.0:8765`，表示接受本机各 IPv4 网络接口的连接；程序并没有只监听 `192.168.2.77`。地址绑定来自下载 URL。服务仅接受本机和 IPv4 私有网段来源。

电脑换 IP 后，必须同时检查三处：手机保存的完整配置链接、MRS 下载 URL、补充 YAML 下载 URL。目前程序不会自动同步修改它们。README 和局域网订阅说明中的地址是文字示例，也应随实际地址更新。

## 固定 IP 属于系统设置

本机 Wi-Fi 曾手动设置为以下 IPv4 配置，记录见[局域网订阅说明](局域网订阅.md)：

- 地址：`192.168.2.77`
- 子网掩码：`255.255.255.0`
- 网关：`192.168.2.1`

复制项目不会把这些系统设置带到另一台电脑。新电脑应使用所在网络可用的地址，两台电脑不能同时使用 `.77`。换到其他网段时，也不能直接照搬这些数值。

本项目没有配置路由器地址保留，迁移步骤也不涉及操作路由器后台。可以先使用新电脑当前的局域网地址完成验证；以后地址变化时，需要同步更新下载链接。

## 换电脑的步骤

### 1. 停止旧电脑上的服务，再复制项目

在旧项目位置停止后台服务，然后复制整个项目目录。Mac 可以双击「停止订阅服务.command」，或在项目目录运行：

```sh
python3 -B project.py subscription stop
```

后台状态文件会记录服务脚本的绝对路径。停止后再搬动目录，可以避免新位置遇到“服务来自另一个项目位置”的错误。状态文件和日志会在新电脑运行时生成，无需复制。

### 2. 准备 Python 并检查文件

项目普通工具需要 Python 3.9+，使用 Python 标准库，不需要额外安装 Python 包。

macOS / Linux：

```sh
python3 -B project.py check
```

Windows：

```powershell
python -B project.py check
```

此检查验证项目校验和、输入快照、生成记录和 Python 语法，不验证手机是否已更新配置，也不连接手机或检查节点可用性。

### 3. 修改三个下载地址

先确认新电脑在手机所在局域网中的 IPv4 地址，再完成以下修改：

1. 将完整配置中两份广告规则 URL 的主机部分从 `192.168.2.77` 改为新电脑地址。
2. 在手机客户端中，将完整配置订阅链接的主机部分也改为新电脑地址。
3. 保留当前端口 `8765`、三个下载路径和规则集名称；这次迁移不需要修改广告拦截策略、DNS 或上网模式。

如果确实需要换端口，目前须修改服务脚本中的端口常量，并同步修改以上三个 URL。只修改下载链接不会改变服务实际监听的端口。

手机链接应填写电脑的局域网地址。`127.0.0.1` 在手机上指手机自身，`0.0.0.0` 是监听地址，都不能代替电脑地址使用。

### 4. 在新电脑启动服务

macOS 后台运行：

```sh
python3 -B project.py subscription start
python3 -B project.py subscription status
```

也可以使用项目里的「启动订阅服务.command」和「查看订阅地址.command」。双击脚本固定调用 `/usr/bin/python3`；若 Python 装在其他位置，可先使用终端中可用的 Python 执行上述命令。

Windows 前台运行：

```powershell
python -B project.py subscription serve
```

Linux 前台运行：

```sh
python3 -B project.py subscription serve
```

前台运行时保持终端开启，使用 `Ctrl+C` 停止。Windows 和 Linux 的后台管理、双击启动和开机启动尚未实现；本文列出的是现有代码提供的入口，未做这两个系统的实机验证。

新电脑的防火墙需要允许手机所在局域网连接 Python 服务的 TCP 8765 端口。若端口被其他程序占用，服务会报错，不会自动接管该程序。

### 5. 从手机确认更新

先在新电脑浏览器打开 `http://127.0.0.1:8765/health`，应显示包含 `"service": "vpn-config"` 和 `"ok": true` 的 JSON。

再从手机访问新电脑地址下的 `/health`。电脑能访问而手机不能时，检查两者是否处于可互通的局域网、客户端是否有本地网络权限，以及防火墙是否放行该端口。

随后在手机客户端更新完整配置，确认原始配置内容随链接更新，并更新两份广告规则集。`/health` 的下载记录会列出本次服务启动以来各文件的请求次数、来源地址和 SHA-256，可用于核对手机是否向新电脑发起下载。下载成功只证明文件已取得，是否载入仍需检查客户端当前使用的配置和规则集。

仅在启动服务时检查状态，并不能证明手机已经切换到新电脑。旧缓存仍可能让广告拦截正常工作，应结合新电脑的下载记录判断。

## 手机调试参数

可选脚本 `phone-tests/test_phone_rules.py` 保存了检查时的目标：

| 参数 | 当前值或用途 |
| --- | --- |
| `HOST` | `192.168.2.199`，手机控制器的局域网地址 |
| `PORT` | `9443`，手机控制器 HTTPS 端口，与电脑订阅端口 8765 无关 |
| `FINGERPRINT` | 当前手机控制器证书的 SHA-256 指纹 |
| `MRS`、`YAML` | 当前完整配置里两份广告规则集的名称 |

如果只更换电脑，而手机地址、证书和规则集名称都保持不变，这些参数可以沿用。换手机或变更控制器配置时，应先核对证书指纹，再测试。密钥由标准输入提供，脚本不保存控制器密钥。

脚本使用 Clash-Client 的 `/clash/v1/rules/match` 扩展接口，不能假定任何 Mihomo 客户端都支持。运行会增加人工规则命中计数，并覆盖 `phone-tests/report.json`；迁移项目本身不需要运行它。

## 可以直接搬移的内容

- 顶层最终规则 `ads-merged.mrs`、`ads-merged-extra.yaml` 和本地文件规则示例不绑定电脑 IP。
- 生成脚本从脚本所在位置定位项目，不要求固定用户名或安装在下载目录。
- 构建、内核测试通过 `--mihomo` 指定可执行文件；换系统或 CPU 架构时，使用相应平台的 Mihomo，项目不捆绑固定的 ARM 内核。部分规则转换脚本另外需要 `curl`。
- Cloudflare、Google、阿里 DoH 地址属于公共 DNS 服务地址，不是本机地址依赖。
- 当前局域网直连使用通用的 `GEOIP,private,DIRECT,no-resolve` 和 `GEOSITE,private,DIRECT`，不再要求给这台电脑单独添加 `/32` 规则。
- 历史日志和测试报告中的旧 IP、用户名路径或 `darwin arm64` 只记录当时环境。保留记录即可，无需全项目替换。

Mac 的运行状态位于 `~/Library/Application Support/vpn-config/`，日志位于 `~/Library/Logs/vpn-config/`。这些路径相对于当前用户生成，不绑定 `luoxin` 这个用户名；但目录布局和后台管理实现依赖 macOS。同一台电脑运行多份项目副本时，会共用状态目录和 8765 端口，目前不支持各副本独立管理服务。

## 迁移后仍有的限制

- 手机更新本地配置和广告规则时，提供服务的电脑需要开机、未休眠且网络可达。普通局域网地址不能从手机移动网络直接访问；已载入的节点和规则可以继续使用。
- 完整配置中的节点是保存的快照。更新本机配置链接不会自动向原服务商获取最新节点。
- 本文完成的是迁移依赖检查和操作说明，未修改本机 IP、服务端口、手机设置或路由器设置。
