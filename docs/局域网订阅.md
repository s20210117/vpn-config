# Mac → 手机配置订阅

电脑维护完整配置，手机通过固定链接下载。只需要首次添加链接，以后修改并保存电脑文件，再在手机点击「立即同步」。

## 手机首次添加

1. Mac 和手机连接同一家庭局域网，Mac 保持开机、唤醒。
2. 在手机 Clash-Client 的「配置中心」添加「配置链接」，填写：

   `http://192.168.2.77:8765/config.yaml`

3. 如导入过程出现「同时登记它的规则」，保持开启。进入该配置详情，在「配置覆写 → 规则方案」选择「原始配置」，让该文件提供完整的节点、规则、策略组和 DNS；部分界面称为「使用原始配置」。不要选择与链接同名的已保存规则方案来代替「原始配置」，方案的 DNS 设置不会因为来源文件更新就自动变成来源的新 DNS。
4. 在配置详情打开「随链接更新」，启用这份配置。以后在配置详情点击「立即同步」下载新版本；如当前隧道未切换到新修订，再断开、重新连接。

界面名称来自本项目核对过的 Clash-Client 源码和简体中文翻译；不同安装版本的入口位置可能略有变化。

## 平时怎么修改

- 修改项目内 `subscription/config.yaml`，保存后立即可下载，不需要重启服务。
- `subscription/original.yaml` 是用户提供的原始快照，作为回退副本，不向网络提供。
- 两条广告规则之后，先执行原有的 `GEOIP,private,DIRECT,no-resolve`、`GEOSITE,private,DIRECT`，再执行 TCP/UDP 上网模式规则，让局域网请求直接连接；已删除单独针对 Mac 的 `192.168.2.77/32` 直连规则。修改前快照为 `subscription/before-lan-rule-cleanup.yaml`。
- 「上网模式」排在策略组首位，组内选项依次为 `PASS`、`DIRECT`、`PROXY`。未保存选择时默认使用 `PASS`；已有客户端选择可能继续保留。修改后同步完整配置即可取得新顺序。
- Clash-Client 的「规则」总览会按目标分组，并按规则条数降序显示；这个显示顺序与策略组顺序、规则执行顺序不同。当前不能通过 YAML 把该页中的「上网模式」固定置顶，客户端需提供相应排序功能。源码依据见 [RulesOverviewView.swift](https://github.com/ProjectClash/Clash-Client/blob/main/apple/ClashClient/Sources/ConfigUI/RulesOverviewView.swift#L1010-L1015)。
- DNS 已单独完善为跟随上网模式的加密 DoH，详见 [DNS 说明](DNS说明.md)。修改 DNS 或其他完整配置字段后，需要同步完整配置，单独刷新规则集不会更新这些字段。
- 外区 App Store 的页面/API、iTunes 接口及下载、mzstatic 静态资源在 `PASS` 下单独交给 `PROXY`。这三条规则位于 NETWORK 上网模式规则之后，`DIRECT` 选择仍会直连；需同步完整配置，详见 [App Store 分流](DNS说明.md#外区-app-store-分流)。
- 两套广告 provider 已改为从本机下载，下载策略指定为 `DIRECT`：`http://192.168.2.77:8765/ads-merged.mrs` 和 `http://192.168.2.77:8765/ads-merged-extra.yaml`。规则集名称、格式与拦截策略不变。修改前的完整配置保存在 `subscription/before-local-rule-downloads.yaml`。
- 第一次切换下载地址，在手机同步完整配置并重新启用；如仍使用缓存，在规则集管理中更新这两份规则集。
- 此后调试规则：修改项目顶层的 `ads-merged.mrs`、`ads-merged-extra.yaml`，手机更新对应规则集；如当前隧道未应用新内容，再重新启用配置。MRS 是二进制文件，应通过构建脚本生成；YAML 可以直接编辑。只改电脑文件不会主动推送到手机，单独同步配置也不保证客户端立即刷新缓存中的规则文件。
- 也可由已获授权的调试会话通过 `clash-cli provider update rule <规则集名称>` 触发更新，仍需提供控制器地址、证书指纹和密钥；项目不保存控制器密钥。更新结果为 `unchanged` 表示已检查但内容未变，并非失败；若接口返回 `pendingApp`，则按提示打开手机 App 继续应用。
- 规则自动检查周期沿用原配置的 86400 秒（一天）。调试时可手动更新，不必等自动检查。手机已缓存两份规则后，日常使用可继续使用缓存；更新规则时需要同一局域网内的 Mac 和服务运行。
- 此局域网链接刷新的是完整配置，并不会自动刷新机场节点订阅。
- 该文件内含现有 46 个节点的快照。服务商新增、更换节点或密码后，需要把对应更新同步到电脑维护的配置中。

完整配置包含节点凭据。按用户要求，`subscription/` 不再被 `.gitignore` 排除，初始化 Git 仓库后可通过普通 `git add .` 将完整配置、备份和验证记录一起提交。该目录仍独立于规则项目的文件校验清单。

## 启动与停止

- 双击根目录「启动订阅服务.command」：启动后台服务，关闭终端后继续运行。
- 双击「停止订阅服务.command」：停止服务。
- 双击「查看订阅地址.command」：显示运行状态和当前局域网地址。

命令行入口：

```sh
python3 project.py subscription start
python3 project.py subscription status
python3 project.py subscription stop
```

Mac 重启或用户注销后，需要重新启动一次。这里使用手动启动的后台进程，因为 macOS 的下载目录权限会阻止登录后台代理直接读取本项目，未安装登录自启服务或扩大磁盘访问权限。若首次通过终端启动时系统询问是否允许访问下载文件夹，需允许这项文件夹访问。

后台状态文件位于 `~/Library/Application Support/vpn-config/subscription.pid`。日志在 `~/Library/Logs/vpn-config/`。服务不记录完整 URL、请求头、密钥或配置内容；仅在进程内存中保存三个公开文件的请求次数、最近请求时间、来源 IP、大小和 SHA-256，便于确认手机是否从 Mac 下载，重启服务后清空。

服务只使用 Python 标准库。移动项目文件夹前先停止服务，在新位置重新启动。

## 地址与访问范围

电脑当前地址为 `192.168.2.77`，端口为 `8765`。2026-11-20 已在 Mac 的 `Wi-Fi` 网络服务中手动固定 IPv4：地址 `192.168.2.77`、子网掩码 `255.255.255.0`、网关 `192.168.2.1`；DNS 沿用此前设置。路由器后台未做地址保留。更换网络或网段时需调整该手动配置，可执行 `networksetup -setdhcp Wi-Fi` 恢复自动获取地址；恢复后如果 IP 变化，手机配置链接及两份规则的下载 URL 都需要一起修改。修改前快照保存在私有目录 `subscription/mac-ip-before.json`。手机自己的 VPN 控制器端口 9090、9443 与这个订阅端口分别使用。

服务仅接受本机和 IPv4 私有网段请求，且只提供以下四个地址，不提供目录浏览或其他项目文件：

| 路径 | 用途 |
| --- | --- |
| `/config.yaml` | 完整手机配置 |
| `/ads-merged.mrs` | 完整配置引用的域名广告规则 |
| `/ads-merged-extra.yaml` | 完整配置引用的广告补充规则 |
| `/health` | 服务状态和文件请求校验记录，不含配置内容 |

这是无认证的 HTTP 局域网服务，同一可信局域网中的设备可以下载配置；不需要 URL 中的用户名、密码或查询参数。不要在路由器上将 8765 端口映射到公网。

Mac 睡眠、关机或服务停止时无法刷新；手机已经保存的配置仍可使用。手机在移动网络、其他 Wi-Fi 时也无法连接此局域网地址进行更新。

## 验证服务

```sh
python3 -B -m unittest discover -s tests -p 'test_subscription_server.py'
python3 project.py check
```

自动测试使用临时模拟配置，验证文件下载、保存后生效、目录和越界路径拒绝、写入拒绝及来源地址过滤，不连接手机，不访问外部网站。

2026-11-20 已通过手机实际验证两份规则的下载来源：从 Mac 发起两次 `clash-cli` 规则更新后，服务记录两份文件的请求均来自手机 `192.168.2.199`，文件 SHA-256 与项目顶层文件一致；手机分别返回 353,223 条和 408 条，结果为 `unchanged`。详细证明保存在私有目录 `subscription/phone-local-source-proof.json`。
